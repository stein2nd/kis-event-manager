# こんなことができたら、良いなぁ

KIS イベント管理は、オンラインセミナーとアーカイブ配信への案内記事を扱うプラグインです。  
いまできること（記事の登録、年別一覧、詳細、申込ボタン、アーカイブ視聴申込との連携）を土台に、将来やりたいことを列挙します。優先度や実装可否はまだ決めていません。

---

## 案内記事そのもの

- 開催日時・形式・参加費以外に、対象者・アジェンダ・登壇者・所要時間も項目として持てる
- 同じテーマのセミナーをシリーズとしてまとめ、前後回へ案内できる
- アイキャッチだけでなく、案内用の短いリード文を一覧カードに出せる
- 記事の途中にも申込ボタンを置ける（本文の最後だけでなく）
- 「こんな人におすすめ」やよくある質問を、本文を毎回書き直さずに差し込める
- 終了後も「当時こういう内容だった」と残しつつ、申込は自然に消える
- 開催日が過ぎたら案内のトーンを「これから」から「アーカイブで見られます」へ切り替えやすい

## 一覧と探しやすさ

- 年タブだけでなく、セミナー / アーカイブ / 終了で絞り込められる
- 「これから開催」だけを先に見せ、過去は後ろや別タブに分けられる
- 年タブを選んだ状態が URL に残り、その年の一覧を共有できる
- 開催日のない記事も、一覧からこぼれ落ちない
- 件数が増えても、全部一度に出さず読みやすくできる
- サイト内の別ページに「直近のセミナーだけ」「アーカイブだけ」を埋め込める
- トップやブログから、次に開催する 1 件を目立たせられる
- カレンダー（月表示）でもイベントを眺められる

## 申込と視聴の案内

- セミナー申込も、アーカイブ視聴申込と同じくサイト内フォームで完結できる
- 申込ボタンの行き先（外部フォーム / サイト内フォーム）を記事ごとに迷わず選べる
- 視聴申込後のメールに、動画 URL だけでなく開催日やタイトルも揃って入る
- YouTube URL の準備前に申し込まれても、「準備でき次第ご案内」と運用しやすい
- 同じ人が何度も同じアーカイブを申し込んだときに、重複が分かる
- 申込完了ページから、ほかのアーカイブや次のセミナーへ自然に誘導できる
- Zoom URL やミーティング ID を、公開ページに出さず申込者にだけ届けられる
- 開催直前のリマインド（当日リマインドメールなど）を出せる

## 公開ページの体験

- 開催までの残り日数や「本日開催」が、詳細ページでも一目で分かる
- ブラウザのカレンダーへ予定を追加できる（ICS）
- イベント情報を検索エンジンや SNS が理解しやすい形で出せる（構造化データ、OGP）
- 終了イベントは申込ボタンが確実に出ず、個別テンプレートと本文フィルターで挙動がずれない
- 一覧へ戻るリンクや申込ページの URL が、固定の日本語スラッグに縛られない
- 年タブをキーボードだけで操作できる
- 関連するアーカイブや、同じテーマの次回セミナーを詳細の末尾に出せる

## 管理画面での運用

- 開催日を過ぎたセミナーを、一覧からまとめて「終了」や「アーカイブ配信」に変えられる
- 管理一覧を開催日や種別で並べ替え・絞り込みできる
- 終了済み警告を、編集画面だけでなく一覧の一括操作のきっかけにできる
- アーカイブ切替時に、YouTube URL が空なら保存前に気づける
- カードや詳細の見た目を、公開前にプレビューしやすい
- よく使う開催形式・参加費・ボタン文言を、毎回手入力しなくても済む
- 一覧ページの見出し文（いまは Forwarder-PRO 向けに固定）を設定画面で変えられる
- MW WP Form のフォーム番号や申込ページのパスを、コードを触らず設定できる

## 公開のタイミングとライフサイクル

- 案内記事を、開催日の何日前かに自動で公開できる
- 開催後、一定期間で自動的に「終了」や「アーカイブ待ち」になる（いまは手動）
- アーカイブの公開期限を決め、期限後は視聴申込を止められる
- 下書き・予約投稿・公開・終了・アーカイブの状態が、運用者に分かりやすい言葉で並ぶ
- 同じセミナーを来年もやるとき、前回記事を複製して日付だけ変えられる

## 計測と改善

- 案内ページの閲覧数と、申込ボタンのクリック数が記事ごとに分かる
- どの年・どの種別の記事がよく見られているか、ざっくり把握できる
- アーカイブ視聴申込が、どの記事から来たかを後から辿れる

## つくりとしての余裕

- ショートコードだけでなく、ブロックエディタから一覧を置ける
- 一覧カード・詳細・年タブの見た目を、テーマ側から上書きしやすい
- 日本語サイト前提のままでも、文言を一箇所で変えられる
- 案内記事用の項目が増えても、入力欄が種別ごとに整理されたまま保たれる
- テストや動作確認の手順が残り、改修しても案内・申込・メールの流れを壊しにくい
